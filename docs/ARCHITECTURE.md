# 架构与恢复规则

## 边界

Core 为 `net10.0`，持有协议、SQLite、稳定实体 ID、操作队列、文件快照和传输逻辑。SwiftUI / AppKit 实现界面；随应用启动的 self-contained C# 引擎承载 Core。两者通过标准输入/输出匿名管道交换带请求 ID 的 JSON 行，无网络监听端口。窗口关闭后菜单栏和引擎继续运行；退出时等待引擎保存队列。

引擎输出仅含响应和状态通知，凭据请求不写日志。每个数据目录使用进程独占租约，防止两个引擎同时执行队列。平台层提供 Keychain / DPAPI 与协调读取，原生桥接只有小型 C ABI。系统打开、文件选择器、弹窗、菜单栏由 AppKit 提供。

应用不注册 Finder File Provider。云端操作与本地缓存文件生命周期分开：删除本地缓存不产生云端删除。

## 持久化

SQLite 使用 WAL 和 FULL synchronous。实体表在引擎内有仅在事务提交后更新的内存副本，状态快照、列目录和预加载不逐次反序列化整表。账号、实体、磁盘树、操作均有持久记录。实体本地 GUID 稳定，云端 ID 可在覆盖上传后替换；离线创建目录的后续任务引用本地 GUID。

每项操作记录账号、目标、依赖、版本基准、快照位置与 SHA-256、状态和恢复证据。依赖未完成时不发送请求。完成操作时更新后续操作的基准；账号切换取消当前请求，原账号任务保持隔离。

上传快照先完整落盘再入队，发送前重查哈希。Mac 通过 NSFileCoordinator 协调复制，前后检查元数据和内容；无法协调其他应用的全部写入，变化的文件延后重试。第三方 Office 保存行为需真机验收。

## 写入与冲突

每次写入重新验证目录 ID、完整列表和 FullAccess。单账号串行执行写入事务；目录上下文锁只保护依赖会话目录的元数据步骤，在携带明确 token、diskid、folderid 的文件传输、直链校验和轮询等待期间释放。工作区允许有上限的并发读取；账号切换先取消旧请求，再排空请求槽后释放客户端。

目录树后台广度优先预加载；单节点失败不阻止其他分支；展开未加载节点的 IPC 不改变当前浏览目录。列表声明大小与直链实测大小分开保存，真实大小按列表版本缓存，修正大小不修改编辑冲突基准。

编辑回传比较原云端 ID、名称、列表版本和基准内容哈希，发现变化暂停，不自动覆盖。用户可接受当前版本继续或另存副本。现有 Web 协议未验证原子条件写，检查与写入之间仍存在并发窗口。

目录导入复用同名目录，文件冲突汇总处理。删除和目录移动需完整子树基准；基准不完整或有新增/改动时人工核对。仅支持同盘移动，禁止移入自身及子目录。

## 恢复

状态：Queued、Running、Uncertain、Blocked、Failed、Completed、Cancelled。进程重启将遗留 Running 改为 Uncertain。开始可能改变云端的请求前保存证据；响应未知时先复查，不能按普通失败重传。

沿用 Windows Stream 上传协议：10 MiB 原始分片、exclusive end、偏移确认、服务端续传、六位后缀候选、新列表轮询、完整下载 SHA-256 复核。发送达 100% 不等于任务完成。

覆盖流程：旧 ID 备份、上传并校验、持久化新 ID、旧 ID 入回收站。恢复时继续核对同一候选，保留未经验证的云端内容。创建目录响应完全丢失且无法唯一确认时停止重复创建，可人工核对后关联新增目录 ID。

未发送操作可取消，依赖一并取消；已发送操作取消后保留核对记录，依赖任务标为需要处理。等待下载校验的上传取消时视为跳过校验并结束，云端文件与覆盖备份保留。任务因取消结束时删除其快照（仍被未结束任务引用的除外），记录保留快照哈希；重试时有变更则要求重新上传。已发送且结果未确认的任务保留快照。任务记录仅在结束（完成或取消）后可删除；“清除已完成”移除已完成记录并解除后续依赖。未同步内容、冲突副本和未知结果的快照不自动清理。退出时保存队列。
