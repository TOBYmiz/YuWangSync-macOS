# 架构与恢复规则

## 边界

Core 为 `net10.0`，持有协议、SQLite、稳定实体 ID、操作队列、文件快照和传输逻辑。SwiftUI / AppKit 实现真正的 macOS 系统界面；一个随应用启动的 self-contained C# 引擎承载 Core。两者通过继承的标准输入/输出匿名管道交换带请求 ID 的 JSON 行，无网络监听端口。窗口关闭后 AppKit 菜单栏和引擎继续运行；退出时等待引擎保存队列。

引擎输出仅包含响应和状态通知，凭据请求不写日志。每个数据目录使用进程独占租约，避免两个引擎同时执行队列。平台层提供 Keychain/DPAPI 与协调读取，原生桥接只有小型 C ABI。系统打开、文件选择器、弹窗、菜单栏由 AppKit 直接提供。

应用不注册 Finder File Provider。界面中的云端操作和本地缓存文件的生命周期分开：本地缓存删除不产生云端删除。

## 持久化

SQLite 使用 WAL 和 FULL synchronous。账号、实体、磁盘树、操作均有持久记录。实体的本地 GUID 保持稳定，云端 ID 可以在覆盖上传后替换；离线创建目录的后续任务引用本地 GUID。

每项操作记录账号、目标、依赖、版本基准、快照位置与 SHA-256、状态和恢复证据。依赖尚未完成时不发送请求。完成自己的操作时更新相关后续操作的基准；账号切换取消当前请求，原账号任务保持隔离。

上传快照先完整落盘再入队，发送前重查哈希。Mac 通过 NSFileCoordinator 协调复制，并在复制前后检查元数据和内容。无法协调其他应用的所有写入，变化的文件会延后重试；第三方 Office 保存行为仍需要真机验收。

## 写入与冲突

每次写入重新验证目录 ID、完整列表和 FullAccess。单账号串行执行写入事务；目录上下文锁只保护依赖会话目录的元数据步骤，在携带明确 token、diskid、folderid 的文件传输、直链校验及轮询等待期间释放。工作区允许有上限的并发读取，账号切换先取消旧请求，再排空请求槽后释放客户端。

目录树采用后台广度优先预加载；单节点失败不阻止其他分支，展开未加载节点的 IPC 不改变当前浏览目录。列表声明大小与直链实测大小分开保存，真实大小按列表版本缓存，修正大小不修改编辑冲突基准。

编辑回传比较原云端 ID、名称、列表版本和基准内容哈希。发现变化暂停，不自动覆盖。用户可以明确接受当前版本继续，或另存副本。现有 Web 协议未验证原子条件写能力，检查与写入之间仍存在并发窗口。

目录导入复用同名目录，文件冲突汇总处理。删除和目录移动需要完整子树基准；基准不完整或有新增/改动时人工核对。仅支持同盘移动，禁止移入自身及子目录。

## 恢复

状态包括 Queued、Running、Uncertain、Blocked、Failed、Completed、Cancelled。进程重启将遗留 Running 改为 Uncertain。开始可能改变云端的请求前保存证据；响应未知时先复查，不能按普通失败重新上传。

沿用 Windows Stream 上传协议：10 MiB 原始分片、exclusive end、偏移确认、服务端续传、六位后缀候选、新鲜列表轮询及完整下载 SHA-256 复核。发送达到 100% 不等于任务完成。

覆盖使用旧 ID 备份、上传并校验、持久化新 ID、旧 ID 入回收站。恢复时继续核对同一候选，保留未经验证的云端内容。创建目录的响应完全丢失且无法唯一确认时停止重复创建，可人工核对后关联新增目录 ID。

未发送操作可取消，其依赖一起取消；已发送操作取消后保留核对记录，依赖它的后续任务显示为需要处理而不是静默等待。等待下载校验的上传取消时视为跳过校验并结束，云端文件与覆盖备份保留。任务因取消而结束时删除其上传快照（仍被未结束任务引用的除外），记录保留快照哈希；重试时仅在源文件哈希未变时重新快照，否则要求重新上传。已发送且结果未确认的任务保留快照。任务记录仅在结束（完成或取消）后可删除；“清除已完成”移除已完成记录并解除后续任务对它们的依赖。未同步内容、冲突副本和未知结果涉及的快照不能自动清理。应用退出保存队列；没有 Mac 本机环境时，不能以 CI 的成功推断真实内网和交互验收已完成。
